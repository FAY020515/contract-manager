# 合同管理系统 · 建设规划与排期

> 版本：2026-11-27 初稿
> 定位：财务审计部内部台账系统，几个人使用，两种角色（管理员 / 普通用户），不需要审批流
> 前提约束：单机运行、局域网访问、备份介质只有 U 盘（多人各自带盘）

---

## 一、什么算"成熟"

不按大企业那套标准。对这套系统，"成熟"就是下面四条能同时成立，每一条都可以当场验收：

| 标准 | 具体含义 | 怎么验证 |
|---|---|---|
| **数据不丢** | 每天自动备份成功、U 盘每周有一份、真的演练过一次恢复 | 设置页显示"上次备份时间"是今天；U 盘里有本周的备份文件夹；演练过一次回到某天且数据正确 |
| **痕迹清楚** | 金额、状态、对方单位、附件的任何变化，都能在合同详情的时间线看到"谁、什么时候、从什么改成什么" | 随便改一条合同的金额，时间线立刻出现"金额 8000 → 9000 · 张三 · 时间" |
| **误操作挡得住** | 删除只给管理员；删合同、恢复备份这类动作都要二次确认；导入坏文件不会毁库 | 用普通账号登录看不到"删除"按钮；导入一个 txt 改名的假备份，提示"不是有效数据库"且数据完好 |
| **能交接** | 换人、换电脑，照着手册能把系统装起来、把数据接上 | 拿一份手册，在一台干净电脑上从零装好并恢复出全部合同与附件 |

## 二、现状基线（2026-11-27）

已经落地并验证过的能力，作为规划的起点：

1. 合同的增删改查、收付款记录、到期提醒、统计图表、Excel 导入导出、列配置
2. 附件与收付款凭证的上传、预览、下载、删除
3. **自动备份含附件**（每份是一个文件夹：台账数据库 + 全部附件副本），可一键恢复台账与附件，恢复前自动留存当前状态
4. **备份失败界面可见**（红色提示写明原因），不再无声无息
5. **数据库原子写盘**，进程被杀或断电不会留下半个库
6. **导入前校验**：无效文件不会覆盖运行中的数据库
7. **admin 密码不再每次启动被重置**
8. **权限边界**：备份类操作仅管理员；删除附件必须登录（此前无需登录，已修）
9. **操作留痕**：合同创建/修改、附件上传/删除、凭证上传/更换/删除，操作人取登录账号
10. 桌面安装包 + 免安装包两个发布物，GitHub Release 可下载

**已知缺口**（本规划要解决的）：普通用户可删合同（且会连带删除附件与日志）、改合同只记一句"更新合同信息"、重复编号报错不友好、收付款记录本身无留痕、README 有过时描述、无使用与运维手册、无自动化体检手段。

## 三、分期计划

### 阶段一：权限与误删防护（最高优先）　✅ 已完成 2026-11-27，随 v2.2.0 发布

1. 删除合同只允许管理员（含连带删除附件与日志这条路径）
2. 删除附件只允许管理员
3. 删除合同时要求手工输入合同编号确认，防止点错
4. 普通用户界面上不出现删除入口（列表行、详情页、附件行）
5. 管理员账号不可把自己降级或删掉（已有规则，补一次实测）

**验收**：用普通账号登录 → 合同列表每行没有"删除"，详情页没有"删除合同"，附件行没有"删除"；同一个账号直接访问删除地址 → 提示"权限不足"。
**工时**：我 0.5 个工作日；你 15 分钟验收。
**影响提醒**：截至 2026-11-27，**同事与使用者本人都还没有开始使用这套系统**（库里没有真实合同），因此权限收紧不需要提前打招呼——反过来，这正是定规则的最好窗口：等大家录了几十个合同再改习惯，成本比现在高得多。今后再变更权限，才需要提前知会。

**完成记录（2026-11-27）**：上述 1–4 全部实现并在隔离环境验证（14 项检查通过：普通用户删除合同与附件均被拒、缺编号或编号不符返回"删除已取消"且数据不动、管理员按编号删除成功、删除附件仍写操作日志）。顺带补了一个原计划外的缺口：**最后一位在职管理员原先可以被降级或停用**（只有"删除"有保护），现已一并拦住。仍在开放的一项：**收付款记录的删除**还没有角色限制，留给阶段二与留痕一起做。

### 阶段二：审计留痕深化（最高优先）　✅ 已完成 2026-11-27，随 v2.3.0 发布

1. 修改合同记录字段级差异：金额、对方单位、状态、结束日期、负责人（旧值 → 新值）
2. 收付款记录的新增、修改、删除写入合同时间线（现在只有凭证有痕迹）
3. 合同列表可显示"最后修改人 / 最后修改时间"两列（默认隐藏，列配置里可打开）

**验收**：把某条合同金额从 8000 改成 9000 → 详情页时间线出现"金额 8000 → 9000"；新增一笔收付款 → 时间线出现"新增收付款：支出 3000 元"。
**工时**：我 1 个工作日；你 15 分钟验收。
**规则已确认（2026-11-27）**：普通用户可以修改合同，不需要管理员审批；责任追溯依靠上面的字段级留痕，不靠限制权限。

**完成记录（2026-11-27）**：1–3 全部实现并在隔离环境验证（14 项检查通过）。实际效果：改合同会记成「合同名称：A → B；合同金额：8,000 元 → 9,000 元」，原值保存记「未检测到字段变化」；新增/修改/删除收付款各记一条，修改只记变化字段；上传或更换凭证不产生"修改收付款"噪音。**顺带补上阶段一留下的口子：删除收付款记录改为仅管理员**，普通用户删除返回 403，管理员删除后时间线留下「删除收付款：支出 3,500 元（待付）」。合同列表新增「最后修改人」「最后修改时间」两列（默认隐藏，列配置里可打开）。

### 阶段三：录入防错　✅ 已完成 2026-11-27，随 v2.4.0 发布

1. 合同编号重复时给出"编号 XXX 已存在，请换一个"的提示（手动新建、编辑、Excel 导入三条路径都要友好提示，现在是数据库英文报错）
2. **提供导入模板下载**：按系统字段生成带示例行与填写说明的 Excel，放在导入弹窗里（当前状态：使用者没有现成台账 Excel，因此改为"系统给标准模板"，不再迁就旧格式）
3. 表头对不上时明确提示"未找到「合同名称」列，请参照模板表头"，而不是逐行报"合同名称不能为空"
4. 日期格式容错：Excel 里的日期单元格（序列号）与"2026/1/5"这类写法统一转成 2026-01-05；无法识别时该行失败并说明原因
5. 复查必填项与金额格式校验，避免存进空名称或负数金额

**验收**：新建一条编号已存在的合同 → 表单红字提示"编号 XXX 已存在"，不跳错误页；下载模板并按示例填两行导入 → 两条都成功，日期显示为 2026-01-05 这样的格式；把表头"合同名称"改成"合同标题"再导入 → 直接提示表头不匹配，而不是逐行报错。
**工时**：我 1 个工作日；你 30 分钟验收（含实际走一遍模板导入）。
**前置**：无（原计划要求的"真实 Excel 样例"已确认不存在，改为系统出模板）。

**完成记录（2026-11-27）**：5 项全部实现并在隔离环境验证（14 项检查通过）。实际效果：重复编号在新建、编辑、导入三条路径都提示「合同编号「X」已存在，请换一个」；空名称与负金额被拒；导入时 Excel 日期序列号（46027）与「2026/3/7」都规范成 YYYY-MM-DD，金额「8,000元」识别为 8000，识别不了的行逐行报原因（第 5 行：合同金额无法识别：约8000）。模板下载升级为两个工作表（合同 + 填写说明，含两条示例）。**过程中发现并修掉一个原有缺陷**：中文表头的 CSV 会被按错误编码解码成乱码，导致表头对不上——现在先按 UTF-8 读、认不出再按 GBK 读一次。

### 阶段四：备份的最后一公里　✅ 已完成 2026-11-27，随 v2.5.0 发布

1. 备份卡片顶部显示"最近一次备份：X 天前"，超过 7 天变黄提醒
2. 首页提醒条：仍在使用默认密码 / 从未做过备份 → 提示并一键跳到设置页
3. 恢复完成后给出结果提示（"已回到 2026-11-20 17:30 的状态，恢复前数据已留存"）
4. 开机自启实测一次（安装包已带该功能，但从未验证）

**验收**：把最近备份删掉模拟"很久没备份" → 卡片变黄；用默认密码登录 → 首页出现提示条。
**工时**：我 1 个工作日；你 30 分钟（含开机自启实测）。

**完成记录（2026-11-27）**：
1. 设置页改为「最近一次备份：X 天前（时间）」，7 天内绿色、超过 7 天橙色并附"建议尽快做一次备份"、从未备份显示"尚未备份"；实测备份后立刻变「0 天前」绿色。
2. 首页提醒条两项：默认密码（管理员可点"去修改"跳到用户管理）、从未备份或超 7 天（可点"去设置"）；实测新环境同时出现两条，文案完整。登录与 `/api/auth/me` 增加了 `usingDefaultPassword` 标记，改密后立即变 false。
3. 恢复成功后弹窗写明恢复到的时间点与"恢复前数据已留存"，按钮"刷新页面"，替代原来一闪而过的提示。
4. **开机自启实测发现两处问题并修复**：`installer.nsh` 从来没被 `electron-builder.yml` 引用（installer.nsh 存在但 `nsis.include` 缺失），历次安装包都没有创建开机启动项；且脚本用 `$SMSTARTUP`（所有用户，需管理员权限），与默认的"仅当前用户"安装不匹配。改为当前用户启动目录 `$APPDATA\Microsoft\Windows\Start Menu\Programs\Startup`（**NSIS 没有 `$STARTUP` 常量**，第一次这么写直接编译失败，已踩过）。**这一项仍需你在装好 v2.5.0 后实测**：重启电脑看系统是否自动拉起。

**同日附带修复（与本阶段无关但影响可信度）**：发现根 `tsconfig.json` 是空壳引用（`"files": []`），一直执行的 `tsc -p tsconfig.json` 从未检查过 `src/`，因此漏掉了"使用未导入的 Modal"这类真实错误。现已改为 `npx tsc -b` 并把它写进 AGENTS.md；顺带清零了因此暴露的 7 处历史类型错误（合同表单文件类型、统计页状态索引、窗口 API 声明缺失等），`tsc -b` 现为 0 错误。

## 四、排期

按"批次"推进，每批一个连续时段做完开发 + 你当场验收 + 打包发布。以周为单位排，约 **5 周**；如果某周空闲，也可 2–3 个工作日连做。

| 批次 | 内容 | 我的时间 | 你的时间 | 前置依赖 |
|---|---|---|---|---|
| 第 1 周 | 阶段一 权限与误删防护　✅ 已完成 | 0.5 天 | 15 分钟 | 无 |
| 第 2 周 | 阶段二 审计留痕深化　✅ 已完成 | 1 天 | 15 分钟 | 第 1 周完成 |
| 第 3 周 | 阶段三 录入防错　✅ 已完成 | 1 天 | 30 分钟 | 你提供一份真实 Excel 样例 |
| 第 4 周 | 阶段四 备份最后一公里　✅ 已完成 | 1 天 | 30 分钟 | 无 |
| 第 5 周 | 阶段五 可交接 | 1.5 天 | 30 分钟 | 前四周完成（手册要写最终形态） |

**每批的固定动作**（已计入上面的工时）：改完代码 → 我在隔离环境实测 → 你验收 → 重新打两个安装包 → 替换 GitHub Release 附件 → 告知你重装。

**总计**：我约 5 个工作日；你需要约 2 小时，分散在 5 次验收里。

**排期的两个现实约束**：

1. 每个批次结束都必须重发安装包，否则同事电脑上跑的还是旧版本——这是固定成本，不是额外工作。
2. 阶段三依赖你提供真实的 Excel 样例；没有样例就顺延，或改成"先只做编号重复提示"。

## 五、风险与应对

1. **权限收紧会改变同事习惯**：上线前由你在群里说明"删除合同需管理员操作"，避免他们以为是系统坏了。
2. **恢复演练可能被跳过**：阶段四之后如果一直没人演练，真出事时不敢用。建议在阶段五手册里写死"每季度演练一次"。
3. **U 盘备份依赖人的记性**：系统能提醒"很久没备份"，但插不插盘只能靠人。若哪天想彻底解决，回到阶段六第 4 项。
4. **单人维护风险**：所有知识目前只在我这边和 AGENTS.md 里。阶段五的手册就是为这个准备的，完成后你自己或 IT 都能接手。

## 七、启用前的准备（当前状态：还没人使用）

系统本身已经能用了，但"能用"和"真的在用"之间还有一段路。下面这些只有你能做，做完这套系统才算真正落地：

1. **装到自己电脑上**：从 v2.2.0 下载安装包，装好后改管理员密码（一次性动作，之后每次启动都不会再被重置）
2. **把字典定成你们的真实口径**：系统设置里的"合同类型"和"部门"，按你们财务审计实际怎么分类来填，不要沿用默认的采购/销售/服务/租赁/劳动/其他。字典定错了，后面统计出来的数字没法用
3. **建同事的账号**：用户管理里逐个建，姓名用真名（操作日志里显示的就是这个名字，这是留痕能不能对上人的关键），角色统一给"普通用户"
4. **准备第一批真实数据**：少量合同可以手工录，几十份以上建议整理成 Excel 用批量导入——**建议先手工录 3～5 份**，把录入流程走顺，再决定要不要批量导
5. **插上 U 盘做一次完整备份**：系统设置 → 备份与恢复 → 填 U 盘路径 → 生成完整备份。这一步做完，才算有了"出事能回来"的底线
6. **约定一个例行节奏**：我的建议是每周五下午插一次 U 盘、点一次生成完整备份（约 1 分钟），并且**每季度做一次恢复演练**（回到某天再回来），否则备份等于没做

**需要你定的一个规则**：合同编号用什么口径？（例如"HT-2026-001"这种带年份流水号，还是直接沿用纸质台账原有编号）——这决定导入阶段要不要做自动编号，以及重复提示怎么写。
