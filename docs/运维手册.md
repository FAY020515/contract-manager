# 合同管理系统 · 运维手册（给管理员 / IT）

> 适用版本：v2.6.0 及以后

---

## 一、东西都在哪

| 内容 | 位置（安装版） | 位置（绿色版/源码） |
|---|---|---|
| 数据库 | `%APPDATA%\合同管理系统\data\contracts.db` | 程序目录 `data\contracts.db` |
| 附件原件 | 同上目录下的 `uploads\` | 程序目录 `data\uploads\` |
| 自动备份 | 同上目录下的 `backups\`（每份是 `auto_backup_时间/` 文件夹，含 db + 附件） | 同左 |
| 程序 | `C:\Program Files\合同管理系统\` | 解压目录 |
| 开机启动快捷方式 | `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\合同管理系统.lnk` | 无 |

> 结论：**换电脑、重装程序都不影响数据**，只要 `data` 目录还在。

---

## 二、备份（最重要）

**自动备份**：程序启动后每小时检查一次，按设置页的频率（每天/每周）往 `backups` 写一份完整备份，保留份数可设。设置页会显示"最近一次备份：X 天前"，超过 7 天变橙色提醒。

**U 盘副本**（建议每周五）：插 U 盘 → 系统设置 → 备份与恢复 →「完整备份到指定目录」填 U 盘路径（如 `F:\合同备份`）→「生成完整备份」。

**恢复**：系统设置 → 备份与恢复 →「刷新列表」→ 选中某份 →「回到所选备份」。注意：
- 台账与附件会一起回到那一刻；之后新增的合同与附件不在系统里；
- 恢复前会自动把当前状态存到 `backups\pre_restore_时间\`（保留最近 3 份），后悔可找回；
- 恢复来源可以是 U 盘上的备份文件夹（在"备份所在文件夹"里填那个路径）。

**建议节奏**：每周一次 U 盘备份，每季度做一次恢复演练（回到某份备份，确认无误后再恢复回最新的）。

## 三、常见故障怎么查

### 1. 服务起不来 / 浏览器打不开

1. 看托盘图标是否存在；不存在就重新双击桌面快捷方式
2. 程序所在的电脑必须开着且没睡眠
3. 若窗口提示"端口被占用"：程序会自动从 3000 往后找端口，窗口里显示的地址以实际为准；仍失败则重启电脑
4. 看日志：状态窗口的地址端口与 `%APPDATA%\合同管理系统\app.log`

### 2. 页面能开，但数据像是丢了

先别慌，按顺序查：

1. 是否换了电脑/重装了程序？——数据在 `%APPDATA%\合同管理系统\data`，确认该目录仍在
2. 是否刚做过"恢复"？——那就是恢复到了旧时点；去 `backups\pre_restore_*` 找回恢复前的状态
3. 打开系统设置 → 备份与恢复 → 刷新列表，看最近备份时间

### 3. 忘记管理员密码

已经取消"重启自动重置密码"（那是安全隐患），改用脚本：

1. **先停止服务**（托盘右键退出，或任务管理器结束「合同管理系统」进程）
2. 在程序源码目录（或任意有 node 的机器上，把 `scripts/` 与 `node_modules` 带上）执行：

```bash
node scripts/reset-admin-password.js
```

3. 脚本会把手里的 `contracts.db` 中 admin 密码重置为 `admin123`；如路径不同，把 db 全路径作为参数传入
4. 启动服务登录，**立即修改密码**

### 4. 开机没有自动启动

检查是否存在 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\合同管理系统.lnk`：

- 有：检查任务管理器 →「启动」里是否被禁用
- 没有：重装一次 v2.5.0 及以上版本安装包（更早的版本此功能未生效）

### 5. 同事打不开局域网地址

1. 确认同事和这台电脑在同一网络
2. 这台电脑的防火墙需放行程序（首次运行会弹窗，选"专用网络"允许）
3. 用 `ipconfig` 确认这台电脑的局域网 IP 是否变了（DHCP 租约变化会导致地址变化）——建议在路由器上给这台电脑固定 IP

## 四、升级程序

1. 关闭正在运行的程序（托盘退出）
2. 运行新版安装包覆盖安装（**不需要卸载旧版**）
3. 打开程序，确认版本与数据正常

数据在 `%APPDATA%` 下，安装器不会触碰。升级前若心里没底，先做一次「完整备份到 U 盘」。

---

## 五、体检脚本

任何改动或怀疑异常时，可在源码目录运行：

```bash
node scripts/smoke.js
```

它会在系统临时目录里复制一份服务、起独立端口跑 13 项核心检查（登录、重复编号、字段级日志、附件、备份含附件、权限拦截、坏文件导入、一键恢复），**不碰真实数据**；全部通过会打印"全部通过"，有失败会列出具体项。

---

## 六、交接要点（给接手的人）

1. 程序所在电脑、`%APPDATA%\合同管理系统\data` 与每周的 U 盘备份，三者缺一不可
2. 管理员账号只有一个时，不要把它降级或停用（程序会拦截）；建议保留一个备用管理员账号
3. 版本号在 GitHub Releases 页面，规划与演进见 `docs/合同管理系统-建设规划与排期.md`
4. 迁移到新电脑：装新程序 → 关闭 → 把旧电脑 `data` 整个目录拷到新电脑同位置 → 启动
